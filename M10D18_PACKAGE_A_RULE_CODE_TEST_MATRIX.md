## Model decisions and blocking evidence

1. **Ability and Nature counters — MODEL OPEN.** `module/data-models.mjs` represents Will/Health as value/max and Nature as current/maximum. It has no per-Ability P/F rows. Role Items have `learning.passed/failed`; these cannot be borrowed as Ability counts. Existing initial values are schema defaults, not historical evidence. The read-only adapter must continue returning no Ability counter baseline. A prospective Legacy-owned optional ledger needs a versioned subject/test/event contract, replay/eligibility rules and migration policy; adding default-zero fields would not recover history. No schema or live storage change in this checkpoint.
2. **Supply increments — MODEL OPEN.** Gear stores quantity/bundle/slots, not a per-Skill supply increment definition or consumed increment ledger. A positive current quantity does not prove one usable increment. Continue requiring the explicit reviewed one-increment assertion and planning zero decrements. A canonical supply classification/unit definition and Legacy-owned spend trace remain required; generic quantity must not be silently interpreted as TB uses.
3. **Entitlements and exceptions — SOURCE/FLOW OPEN.** Class/stock/level benefits, Instinct, Nature channel/substitution, crafting Nature, Versus/ties, Wise lifetime choices and series/conflicts need reviewed source mappings and actual integrated cases. A safe refusal is useful engineering evidence but does not close the required rule.
4. **Current versus historical — G3 OPEN.** Observed native saved faces and current documents plus timestamps/GM declarations do not authenticate state/permission/resources/consent at roll time. Legacy HTML-only original results are unrecoverable from current evidence; prospective retesting is required. Client flags alone cannot change authentication to true.
